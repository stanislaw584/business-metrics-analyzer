# Ответы на контрольные вопросы

Практическое занятие № 1. Настройка среды разработки и управление версиями.

## 1. Чем отличается Git от GitHub?

Git — распределённая система контроля версий, которая работает локально и хранит историю изменений проекта. GitHub — облачная платформа для хранения Git-репозиториев и совместной работы: на ней находятся удалённые репозитории, Pull Request, обсуждение кода и управление задачами.

## 2. Для чего используется виртуальное окружение Python?

Виртуальное окружение изолирует зависимости проекта от системного Python и от других проектов. Каждый проект получает собственный набор библиотек и версий, поэтому не возникает конфликтов. Список зависимостей в `requirements.txt` позволяет воспроизвести окружение на другом компьютере.

## 3. Что такое commit, branch, remote, pull request?

- **Commit** — фиксация изменений в истории проекта с сообщением и автором.
- **Branch** — отдельная ветка разработки, в которой можно вносить изменения независимо от основной.
- **Remote** — удалённый репозиторий, с которым синхронизируется локальный (обычно `origin`).
- **Pull Request (PR)** — запрос на слияние изменений из одной ветки в другую с возможностью проверки кода и комментариев.

## 4. Зачем нужен файл .gitignore?

В файле перечислены файлы и папки, которые не должны попадать в репозиторий: виртуальное окружение, кэш Python, секреты в `.env`, настройки IDE, временные файлы и большие файлы данных. Это уменьшает размер репозитория и защищает конфиденциальные данные.

## 5. Как организовать командную работу над бизнес-приложением с помощью Git?

Ветка `main` остаётся стабильной, а каждая задача разрабатывается в отдельной ветке, например `feature/название`. Изменения публикуются в удалённый репозиторий (`git push`), оформляются в Pull Request и проходят код-ревью у коллеги. После одобрения выполняется слияние, участники обновляют локальную `main` командой `git pull`. Сообщения коммитов должны быть понятными, а задачи разбиты на небольшие части.

## 6. Какие файлы обязательно должны быть в репозитории учебного проекта?

- `README.md` с описанием проекта и инструкцией по запуску;
- `.gitignore`;
- `requirements.txt` со списком зависимостей;
- исходный код (`main.py` и модули);
- документация проекта в папке `docs`, например `business_requirements.md`.

## 7. Что произойдёт, если два разработчика изменят один и тот же файл в разных ветках?

Если изменены разные участки файла, Git объединит правки автоматически. Если правки затрагивают одни и те же строки, при слиянии возникнет конфликт. Git отметит спорные места маркерами, разработчики должны вручную выбрать итоговый вариант, добавить файл в индекс (`git add`) и завершить слияние коммитом.
